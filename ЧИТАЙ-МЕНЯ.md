# Ikhlas — трекер привычек (ikhlas.website)

Самостоятельный сайт: своя база `sulmin_ikhlas`, свои аккаунты, весь код внутри
этой папки. Никаких внешних зависимостей, кроме входа через Google.

## Как выложить

1. Залить **содержимое этой папки** (не саму папку) в корень сайта `ikhlas.website`
   — на Beget это `~/ikhlas.website/public_html/`.
2. В панели Beget создать базу **`sulmin_ikhlas`** с пользователем `sulmin_ikhlas`
   и паролем, который уже прописан в `includes/db.php`.
   Больше ничего в базе делать не нужно — таблицы создадутся сами
   при первом открытии сайта.
3. Включить SSL для домена. Google Sign-In работает только по HTTPS.
4. **Настроить кнопку «Войти через Google»** — см. раздел ниже.
5. Открыть `https://ikhlas.website` → войти через Google.

## Вход через Google — настройка

Вход на сайт устроен только через Google: своих паролей нет, аккаунт создаётся
из Google-профиля. Google пускает кнопку работать лишь с тех адресов, которые
заранее записаны у него в настройках. Поэтому один раз надо туда зайти.

> **Где это в консоли.** Google переименовал раздел: то, что раньше было
> «APIs & Services → Credentials / OAuth consent screen», теперь называется
> **Google Auth Platform**. Если искать через поиск вверху — набрать
> `oauth client` и выбрать первый результат, **Google Auth Platform**
> (не «Identity platform» — это другой продукт).
>
> Внутри слева нужны два пункта:
> **Clients** — бывшие OAuth 2.0 Client IDs (сами ключи и домены);
> **Audience** — бывший OAuth consent screen (статус публикации).

### Шаг 0. Проверить, есть ли уже проект

Открыть <https://console.cloud.google.com/auth/clients> и посмотреть
список проектов вверху слева.

- Проект **tracker** (`tracker-486613`, номер `476412427816`) есть →
  **вариант A**, просто дописать домен.
- Проекта нет (или зашёл под другим Google-аккаунтом) → **вариант Б**,
  создать с нуля.

Подсказка: число до дефиса в Client ID — это и есть номер проекта.
`476412427816-csitmrml…` → проект с номером `476412427816`. Так можно
понять, от какого проекта ключ, не заходя никуда.

### Вариант A. Проект уже есть — дописать домен

Прямая ссылка: <https://console.cloud.google.com/auth/clients?project=tracker-486613>

1. Слева **Clients** → нажать на клиент `476412427816-csitmrml…`.
2. Блок **Authorized JavaScript origins** → **+ ADD URI** →
   вписать ровно `https://ikhlas.website` (без слеша в конце, обязательно `https`).
3. Если в списке есть старые адреса — можно оставить, они не мешают.
4. **SAVE**. Работает сразу, изредка — до 5 минут.
5. Слева **Audience** → посмотреть Publishing status.
   Если **Testing** — нажать **PUBLISH APP**. Если **In production** — не трогать.

Менять `includes/google_config.php` в этом случае НЕ нужно.

### Вариант Б. Проекта нет — создать с нуля

1. <https://console.cloud.google.com/> → вверху слева выпадающий список
   проектов → **NEW PROJECT** → имя, например `ikhlas` → **CREATE**.
   Дождаться, пока проект создастся, и выбрать его.

2. **Настроить экран согласия** (то окно, где Google спрашивает «продолжить
   как …»). Открыть **Google Auth Platform** → **Branding** / GET STARTED:
   - App name: `Трекер привычек`
   - User support email: свой ящик
   - Audience: **External**
   - Developer contact information: тот же ящик
   - Остальное можно не заполнять

3. **Опубликовать.** Google Auth Platform → **Audience** →
   **PUBLISH APP** → подтвердить. Без этого войти смогут только те аккаунты,
   которые вручную добавлены в Test users.
   Проверка Google тут не требуется: сайт просит только имя и почту,
   а это базовые данные — публикация проходит мгновенно.

4. **Создать сам ключ.** Google Auth Platform → **Clients** →
   **+ CREATE CLIENT**:
   - Application type: **Web application**
   - Name: `ikhlas.website`
   - **Authorized JavaScript origins** → + ADD URI → `https://ikhlas.website`
   - Authorized redirect URIs — **оставить пустым**, они не используются
   - **CREATE**

5. Google покажет **Client ID** вида `1234567890-abcdef….apps.googleusercontent.com`.
   Скопировать его. **Client secret не нужен**, его можно игнорировать —
   сайт проверяет ID-токен, а не обменивает код на сервере.

6. Вставить этот Client ID в файл **`includes/google_config.php`** —
   там одна строка, заменить значение в кавычках:

   ```php
   define('GOOGLE_CLIENT_ID', 'СЮДА_НОВЫЙ_CLIENT_ID');
   ```

   Залить файл на сервер. Всё.

### Сайт обязан работать по https

Вход через Google по `http://` невозможен в принципе: адрес вида
`http://ikhlas.website` нельзя зарегистрировать в Authorized JavaScript
origins — Google принимает только `https` (единственное исключение —
localhost при разработке).

Поэтому: сначала SSL, потом вход. В `.htaccess` уже стоит принудительная
переадресация с http на https — она включится сама, как только сертификат
заработает. Если сертификата ещё нет, а файл уже залит, сайт будет уводить
на https и показывать предупреждение браузера: тогда временно закомментируй
блок `RewriteEngine On` в `.htaccess`.

### Если кнопка не работает

Нажимается, но ничего не происходит — почти всегда домен не совпадает.
Открыть консоль браузера (F12 → Console), там будет видно:

- `origin_mismatch` → в Authorized JavaScript origins не тот адрес.
  Частые причины: слеш в конце, `http` вместо `https`, `www.ikhlas.website`
  вместо `ikhlas.website` (это для Google два разных адреса — добавь оба).
- `invalid_client` / `deleted_client` → Client ID в `google_config.php`
  не существует. Значит проект или ключ не тот — вариант Б.
- `access_blocked` → приложение не опубликовано (шаг 3 варианта Б).

## Что внутри

```
index.php              вход → перенаправление на login или habits
login.php              страница входа (только кнопка Google)
google_auth.php        приём ID-токена Google, создание/поиск аккаунта
logout.php             выход
habits.php             сам трекер (интерфейс)
api/habits.php         REST: привычки, отметки, дни
finance.php            раздел «Финансы» (интерфейс)
api/finance.php        REST: категории и подкатегории, семья, быстрые кнопки, операции
includes/db.php        подключение к базе  ← пароль здесь
includes/auth.php      сессия
includes/google_config.php  Google client_id
includes/theme.php     темы оформления
.htaccess              закрывает конфиги от прямого доступа
```

## Таблицы (создаются автоматически)

`google_users` — аккаунты, вошедшие через Google
`habit_defs` — список привычек пользователя
`habit_logs` — отметки по дням
`habit_days` — сводка по дню

`fin_cats` — категории финансов; у подкатегории заполнен `parent_id`
(ссылка на категорию), у категории он пустой. Вложенность — два уровня.
`fin_people` — члены семьи для поля «Для кого»
`fin_quick` — кнопки быстрого ввода
`fin_tx` — операции (расходы и поступления)

## Финансы

Раздел живёт в той же базе `sulmin_ikhlas` и пускает по тому же входу через
Google — отдельной установки, своих логинов и паролей у него нет.
У каждого пользователя свои категории и операции, чужие не видны.
При первом открытии раздела пользователю создаётся стартовый набор категорий
(с примерами подкатегорий у «Продуктов» и «Коммуналки»).

Категории и подкатегории удаляются «мягко»: из выбора пропадают, а старые
операции и отчёты по ним остаются с прежними названиями.

## Первый вход

Первый вошедший через Google становится обычным пользователем — отдельной роли
администратора здесь нет, у каждого свой личный набор привычек и своя статистика.

## Библиотека

Раздел `/library/` — личная электронная библиотека: EPUB, FB2, MOBI, AZW3, PDF, DjVu,
TXT, DOCX, RTF; чтение в браузере, синхронизация места чтения и заметок между устройствами,
офлайн-режим, распознавание сканов, архив и восстановление.

- Видна только почтам из `includes/lib_config.php` → `LIB_ALLOWED_EMAILS`.
- Таблицы `lib_*` и папка для книг `~/ikhlas.website/library_storage` (вне `public_html`)
  создаются сами при первом открытии раздела.
- Всё подробно — архитектура, установка, таблица форматов, синхронизация, резервные копии,
  результаты тестов, ограничения и план — в файле **БИБЛИОТЕКА.md**.
